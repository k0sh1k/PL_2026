# Построчный разбор кода решателя (Билет №6) — текстовая версия

Это объяснение кода `solver.py` строка за строкой, прозой. Можно читать отдельно
от кода, как сопроводительный текст. Сначала разобран решатель Варианта 3, затем —
что добавлено в Варианте 2 (ввод числа пересечений).

═══════════════════════════════════════════════════════════════════════
ЧАСТЬ 1. РЕШАТЕЛЬ ВАРИАНТА 3
═══════════════════════════════════════════════════════════════════════

── Шапка файла ──

Первая строка `# coding: utf-8` сообщает Python, что файл в кодировке UTF-8 —
без неё русские буквы в комментариях могли бы вызвать ошибку.

Дальше идёт большой комментарий-блок, объясняющий назначение файла: это НЕ графика,
а отдельный расчётный модуль. Он вычисляет безопасную расстановку планет и пишет её
в текстовый файл, который потом читает графика. Идея разделения: тяжёлый подбор
делается один раз здесь, а анимация остаётся лёгкой.

── Импорты ──

`import math` подключает математические функции: косинус и синус (для движения по
кругу), число пи, квадратный корень и экспоненту (последняя нужна для отжига).

`import random` подключает генератор случайных чисел — он нужен, потому что метод
подбора (имитация отжига) основан на случайных пробах.

── Параметры ──

`BASE_STEP = 0.01` — это базовый шаг угла за один «тик» времени. Ключевая идея всей
работы: скорость каждой планеты равна целому числу, умноженному на этот шаг. Из-за
кратности скоростей движение получается периодичным — повторяется через определённое
время. На этом строится доказательство отсутствия столкновений.

`PERIOD_TICKS = int(round(2 * math.pi / BASE_STEP))` — сколько тиков длится полный
период. Полный оборот — это угол 2·пи. За тик угол растёт на BASE_STEP, значит на
полный круг уходит 2·пи / BASE_STEP тиков. round округляет, int делает целым. При
шаге 0.01 получается примерно 628 тиков.

`PLANET_RADIUS = 4` — радиус кружка планеты в пикселях. Нужен, чтобы понимать, когда
две планеты «столкнулись» (их кружки наложились).

`REQUIRED_GAP = PLANET_RADIUS * 2 + 2` — какой зазор между центрами планет считаем
безопасным. Два радиуса — это диаметр (кружки едва касаются), плюс 2 пикселя запаса.
Итого 10 пикселей. Если центры дальше этого — планеты гарантированно не налезают.

`CENTER_X, CENTER_Y = 500, 400` — центр экрана (окно 1000×800). Относительно этой
точки расставляются обе звезды.

`STAR_DISTANCE = 460` — расстояние между звёздами в пикселях. Подобрано так, чтобы
орбиты двух звёзд пересекались (внешние орбиты заходят друг на друга), но система не
была переполнена. Это и есть выполнение условия «орбиты звёзд пересекаются».

`R1 = [60 + n * 12 for n in range(1, 17)]` — список радиусов 16 орбит первой звезды.
Конструкция `for n in range(1, 17)` даёт номера 1..16. Для каждого радиус равен
60 + n·12, то есть орбиты 72, 84, 96 и так далее до 252. Чем дальше орбита, тем
больше радиус; все радиусы разные.

`R2 = [60 + n * 10 for n in range(1, 21)]` — то же для 20 орбит второй звезды:
70, 80, ... , 260.

`MOONS1 = {8, 10, 13}` и `MOONS2 = {10, 15, 20}` — номера планет, у которых есть
спутник (по условию билета). Фигурные скобки создают множество — это позволяет
быстро проверять «есть ли номер внутри».

── Функция make_bodies: создание тел ──

Функция создаёт все движущиеся тела обеих звёзд.

`s1x = CENTER_X - STAR_DISTANCE / 2` и `s2x = CENTER_X + STAR_DISTANCE / 2` — это
координаты x двух звёзд: первая левее центра на пол-расстояния, вторая правее.
Так звёзды симметричны, и между ними ровно STAR_DISTANCE.

`b1 = []` и `b2 = []` — два пустых списка для тел первой и второй звезды.

Дальше цикл `for idx, n in enumerate(range(1, 17))` перебирает орбиты первой звезды.
Здесь `enumerate` даёт две вещи сразу: idx — позицию (0, 1, 2...) и n — номер орбиты
(1, 2, 3...). idx нужен, чтобы взять радиус из списка R1 по позиции.

`r = R1[idx]` — радиус текущей орбиты.

`sign = 1 if n % 2 == 0 else -1` — знак скорости, то есть направление вращения.
Выражение `n % 2` — это остаток от деления номера на 2: если он равен нулю, номер
чётный. Для чётной орбиты sign = +1 (по часовой), для нечётной −1 (против часовой).
Это прямое выполнение требования билета про направление по чётности.

Затем `b1.append({...})` добавляет планету. Планета — это словарь с полями: центр
орбиты по x и y, радиус орбиты, множитель скорости k, стартовый угол phase, цвет,
номер звезды и признак is_moon (является ли спутником). Поле k вычисляется как
sign·(16−n+1): множитель (16−n+1) делает внешние орбиты медленнее (для первой орбиты
это 16, для последней 1), а sign задаёт направление. Это лишь стартовое значение —
отжиг потом подберёт величину заново. star_id равен 1, потому что это первая звезда.

Если номер планеты есть в MOONS1, добавляется ещё одно тело — спутник. Его радиус на
7 пикселей больше (летит чуть дальше планеты), скорость и направление те же (летят
вместе), цвет белый, is_moon = True.

Второй цикл `for idx, n in enumerate(range(1, 21))` делает то же самое для 20 орбит
второй звезды, с центром s2x, другим цветом и star_id = 2.

`return b1, b2, s1x, s2x` — функция возвращает тела обеих звёзд и координаты звёзд.

── Функция min_gap: проверка столкновений ──

Это сердце проверки. Функция прогоняет один полный период и находит самое маленькое
расстояние, на которое за это время сближались тела РАЗНЫХ звёзд.

`md = 1e30` — начальное значение «минимальной дистанции». Это очень большое число
(10 в 30 степени), чтобы любое реальное расстояние оказалось меньше и заменило его.

`for t in range(0, PERIOD_TICKS, step)` — цикл по времени: t принимает значения 0,
step, 2·step и так далее до конца периода. Параметр step задаёт, насколько часто
проверять: 1 — каждый тик (точно), больше — реже (быстрее, но грубее).

Дальше две строки строят списки координат p1 и p2 — положения всех тел первой и
второй звезды в момент t. Для каждого тела угол считается как phase + k·BASE_STEP·t
(стартовый угол плюс пройденный за время t), а координаты по формуле движения по
кругу: x = центр_x + радиус·cos(угол), y = центр_y + радиус·sin(угол).

Затем двойной цикл `for x1, y1 in p1` и внутри `for x2, y2 in p2` перебирает каждую
пару «тело первой звезды — тело второй звезды». Важно: тела одной звезды между собой
не сравниваются, потому что у них разные радиусы орбит — это вложенные окружности,
они не пересекаются, и столкнуться им негде.

`d = (x1 - x2) ** 2 + (y1 - y2) ** 2` — квадрат расстояния между двумя телами.
Считается именно квадрат, без извлечения корня, потому что так быстрее, а для
сравнения «кто ближе» корень не нужен.

`if d < md: md = d` — если нашли расстояние меньше текущего минимума, запоминаем его.

`return math.sqrt(md)` — в конце берётся квадратный корень из минимального квадрата,
чтобы получить настоящее расстояние в пикселях.

── Функция solve: имитация отжига ──

Это главный алгоритм подбора. Он меняет стартовые углы и величины скоростей планет
так, чтобы минимальный зазор стал большим. Метод называется «имитация отжига» — он
делает случайные пробы и постепенно «остывает», всё реже соглашаясь на ухудшения.

`random.seed(seed)` фиксирует генератор случайных чисел. С одним и тем же зерном
результат повторяется при каждом запуске — это удобно для отладки и воспроизводимости.

Затем цикл по всем телам делает стартовую «перемешку»: каждому телу ставится
случайный стартовый угол от 0 до 2·пи, запоминается знак скорости (направление по
чётности, его трогать нельзя), и ставится случайная величина скорости от 1 до 18 с
сохранением знака.

Вложенная функция `new_k(old)` выдаёт новую величину скорости с тем же знаком, что у
старой. Она нужна, чтобы при пробах менять скорость, но не направление вращения.

Вложенная функция `anneal(step, iterations, T0)` — один проход отжига. Параметры:
step — точность проверки зазора, iterations — сколько проб сделать, T0 — стартовая
«температура» (чем выше, тем охотнее принимаются ухудшения).

Внутри: `cur` — текущий зазор, `best` — лучший за всё время, `best_state` — копия
лучшей расстановки (углы и скорости всех тел), чтобы вернуться к ней в конце.
`T = T0` — текущая температура, она будет уменьшаться.

Главный цикл повторяется iterations раз. В каждой пробе:
— выбирается случайное тело;
— с вероятностью 60% меняется его стартовый угол, иначе (40%) — величина скорости;
старое значение запоминается, чтобы можно было откатить;
— считается новый зазор cand после изменения;
— решение «принять или откатить»: изменение принимается, если зазор не ухудшился
(cand ≥ cur), ИЛИ — иногда — даже если ухудшился, с вероятностью exp((cand−cur)/T)·0.1.
Этот приём ухудшений нужен, чтобы не застрять в «тупике» (локальном оптимуме). Запись
max(T, 1e-3) защищает от деления на ноль, когда температура почти нулевая;
— если принятый зазор лучший за всё время, он и расстановка запоминаются;
— если изменение не приняли, телу возвращается старое значение;
— температура чуть уменьшается (T *= 0.9995) — система «остывает»;
— если зазор уже заметно больше нужного (с запасом 40%), цикл прерывается досрочно
для скорости.

После всех проб цикл по zip(...) возвращает каждому телу его лучшие найденные угол и
скорость — то есть восстанавливает лучшую расстановку.

В самом конце solve вызывает anneal дважды. Первый раз — грубо: проверка через каждые
3 тика (быстро), 2000 проб, чтобы быстро найти хорошую область. Второй раз — точно:
проверка на каждом тике (step=1), 2500 проб. Важно, что финальная проверка идёт
именно на step=1, иначе грубая сетка могла бы пропустить сближение между тиками, и
зазор оказался бы ложным (это была реальная ошибка на одном из этапов разработки).

── Функция save_config: запись в файл ──

Записывает итоговую расстановку в текстовый файл для графики.

Вложенная функция `line(b)` превращает одно тело в строку текста. Сначала
определяется имя типа (Satellite для спутника, иначе Planet) и радиус кружка (2 для
спутника, иначе 4). Затем строка собирается в формате: тип, радиус, цвет, номер
звезды, центр x, центр y, радиус орбиты, k, фаза. Спецификаторы %s, %d, %.1f, %.6f
означают строку, целое, число с одним и с шестью знаками после точки.

Список `lines` начинается с комментариев (строки с #, поясняющие формат), затем идёт
заголовок и строка первой звезды. Строки всех тел первой звезды добавляются через
`[line(b) for b in b1]`. Потом заголовок и строка второй звезды, и строки её тел.

`with open(filename, "w", encoding="utf-8") as f` открывает файл на запись в кодировке
UTF-8; конструкция with гарантирует, что файл закроется сам. `f.write("\n".join(lines)
+ "\n")` склеивает все строки через перевод строки и записывает.

── Функция main: связывает всё вместе ──

Печатает заголовок, затем создаёт тела через make_bodies.

`cross = sum(1 for a in R1 for b in R2 if abs(a - b) < STAR_DISTANCE < a + b)` —
считает, сколько пар орбит пересекается. Перебираются все пары радиусов (a из первой
звезды, b из второй), и две окружности с центрами на расстоянии D пересекаются, когда
|a−b| < D < a+b. sum(1 for ...) подсчитывает число выполнений условия.

Дальше печатается расстояние между звёздами и число пересекающихся пар с процентом.
Затем сообщается о начале подбора, вызывается solve, после чего итоговый зазор
считается точно через min_gap со step=1 — это честная финальная проверка. Печатается
зазор и вывод: безопасно, если зазор больше диаметра. Наконец save_config записывает
результат в файл, и печатается сообщение о готовности.

Последние строки `if __name__ == "__main__": main()` означают: если файл запущен
напрямую (а не импортирован как модуль), выполнить функцию main.

ЧАСТЬ 2. ЧТО ДОБАВЛЕНО В ВАРИАНТЕ 2
═══════════════════════════════════════════════════════════════════════

Вариант 2 отличается тем, что пользователь сам вводит число пересечений. Добавлены
параметры и две функции, остальное совпадает с Вариантом 3.

── Новые параметры ──

`MAX_WORKABLE_CROSSINGS = 100` — верхняя граница выбора. До 100 пересечений планеты
нормального размера ещё свободно расходятся; выше система становится слишком тесной.
Поэтому больше 100 ввести нельзя. Граница определена экспериментально.

`MIN_CROSSINGS = 1` — нижняя граница: хотя бы одна пара орбит должна пересекаться,
иначе условие билета вообще не выполнено.

`TOTAL_PAIRS = len(R1) * len(R2)` — всего пар орбит, 16·20 = 320. Нужно для показа
процента.

── Функция cross_count(D) ──

Считает число пересекающихся пар орбит при заданном расстоянии D между звёздами. Это
тот же подсчёт, что в main Варианта 3 (условие |a−b| < D < a+b), но вынесенный в
отдельную функцию, потому что он нужен многократно при подборе расстояния.

── Функция find_distance_for(target) ──

Решает обратную задачу: по желаемому числу пересечений находит подходящее расстояние
между звёздами. Принцип: чем ближе звёзды, тем больше орбит пересекается. Функция
перебирает расстояния D от 150 до 510 пикселей с шагом 2 (нижняя граница 150, чтобы
звёзды не слились), для каждого считает число пересечений через cross_count, и
запоминает то расстояние, при котором число пересечений ближе всего к желаемому.
Возвращает лучшее расстояние и реально достижимое при нём число пересечений (точное
попадание не всегда возможно, поэтому берётся ближайшее).

── Функция ask_crossings ──

Спрашивает у пользователя число и проверяет корректность ввода. Сначала печатает
пояснения: сколько всего пар, какой диапазон допустим, и почему есть верхний предел.
Затем входит в бесконечный цикл `while True`, который повторяется, пока не получит
корректное число.

Внутри цикла блок `try ... except` пытается прочитать строку через input и превратить
её в целое число функцией int. Если введено не число, возникает ошибка ValueError
(или EOFError, если ввод оборвался) — тогда печатается сообщение и цикл повторяется.

Если число прочитано, проверяются границы: если меньше минимума — сообщение «слишком
мало», если больше максимума — «слишком много», и в обоих случаях цикл повторяется.
Если число в допустимых границах, оно возвращается, и функция завершается.

── Изменения в main ──

Главная функция Варианта 2 начинается с вызова ask_crossings — получает желаемое
число пересечений. Затем find_distance_for переводит это число в расстояние D и
сообщает реально достижимое число пересечений. Печатается выбор пользователя и
найденное расстояние. Дальше всё как в Варианте 3: создаются тела, запускается отжиг,
считается итоговый зазор, печатается результат, записывается конфиг. В конце —
подсказка запустить графику.

КРАТКО О ГЛАВНЫХ ИДЕЯХ (для устного ответа)
═══════════════════════════════════════════════════════════════════════

1. Скорости планет кратны общему шагу → движение периодично → достаточно проверить
   один период, чтобы гарантировать отсутствие столкновений навсегда.

2. Проверяются только пары планет разных звёзд: внутри одной звезды орбиты
   концентрические и пересечься не могут.

3. Расстояние между телами сравнивается через квадрат (без корня) для скорости.

4. Безопасная расстановка ищется имитацией отжига: случайные пробы фаз и скоростей с
   постепенным «остыванием» и редким приёмом ухудшений, чтобы не застрять в тупике.

5. Знак скорости фиксирован по чётности орбиты (направление вращения — требование
   билета), оптимизируется только величина скорости и стартовый угол.

6. Финальная проверка зазора идёт на каждом тике, иначе грубая сетка пропустила бы
   сближения между тиками.

7. Расчёт вынесен в отдельный модуль (решатель), графика только читает готовый
   результат — так анимация остаётся лёгкой, а тяжёлый подбор делается один раз.
