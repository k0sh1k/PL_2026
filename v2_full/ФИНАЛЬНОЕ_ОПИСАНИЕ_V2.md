# 1. Общая архитектура Варианта 2

Вариант 2 состоит из **двух** программ и одного файла данных:

- **`solver.py`** (решатель) — вычисляет безопасную расстановку планет. Спрашивает у
  пользователя, сколько пар орбит должны пересекаться, подбирает под это конфигурацию
  и записывает её в текстовый файл. Запускается один раз.
- **`solar_main.py`** (графика) — читает готовую конфигурацию и показывает анимацию.
  Ничего не вычисляет.
- **`ticket6_state.txt`** — текстовый файл с результатом работы решателя (его читает
  графика).

Принцип разделения: тяжёлый подбор вынесен в отдельный модуль. Решатель работает
один раз и сохраняет ответ; графика потом просто читает готовое и работает быстро.

Отличие Варианта 2 от Варианта 3: в Варианте 2 пользователь сам задаёт **число
пересечений** орбит, и решатель подбирает под это расстояние между звёздами.

# 2. Файл `solver.py` — решатель

Сначала параметры (константы), затем восемь функций.

## 2.0. Параметры (константы модуля)

- `BASE_STEP = 0.01` — базовый шаг угла за один тик времени. Скорость каждой планеты
  равна (целое число) × BASE_STEP. Из-за кратности скоростей движение периодично.
- `PERIOD_TICKS = int(round(2 * math.pi / BASE_STEP))` — длина полного периода в
  тиках. Полный оборот = 2π, за тик угол растёт на BASE_STEP, значит период =
  2π/BASE_STEP ≈ 628 тиков.
- `PLANET_RADIUS = 4` — радиус кружка планеты на экране (пиксели).
- `REQUIRED_GAP = PLANET_RADIUS * 2 + 2` — безопасный зазор между центрами планет:
  диаметр (2 радиуса) плюс 2 пикселя запаса = 10 пикселей.
- `CENTER_X, CENTER_Y = 500, 400` — центр экрана, относительно него ставятся звёзды.
- `R1 = [60 + n * 12 for n in range(1, 17)]` — радиусы 16 орбит первой звезды:
  72, 84, …, 252.
- `R2 = [60 + n * 10 for n in range(1, 21)]` — радиусы 20 орбит второй звезды:
  70, 80, …, 260.
- `MOONS1 = {8, 10, 13}`, `MOONS2 = {10, 15, 20}` — номера планет со спутниками.
- `MAX_WORKABLE_CROSSINGS = 100` — верхняя граница выбора числа пересечений (выше
  планеты нормального размера не помещаются).
- `MIN_CROSSINGS = 1` — нижняя граница (хотя бы одна пара орбит должна пересекаться).
- `TOTAL_PAIRS = len(R1) * len(R2)` — всего пар орбит: 16 × 20 = 320.

## 2.1. Функция `cross_count(D)`

**Назначение.** Посчитать, сколько пар орбит двух звёзд пересекается при заданном
расстоянии `D` между звёздами.

**Входные данные.** `D` — расстояние между центрами звёзд (число, пиксели).

**Выходные данные.** Целое число — количество пересекающихся пар орбит.

**Алгоритм и математика.** Перебираются все пары радиусов (`a` из R1, `b` из R2).
Две окружности с радиусами `a` и `b`, центры которых на расстоянии `D`, пересекаются
тогда и только тогда, когда выполнено условие:

```
|a − b| < D < a + b
```

- `|a − b| < D` — окружности не вложены друг в друга (расстояние между центрами
  больше разницы радиусов);
- `D < a + b` — окружности дотягиваются друг до друга (центры ближе суммы радиусов).

Функция считает, для скольких пар оба неравенства верны. Реализована через
`sum(1 for a in R1 for b in R2 if abs(a - b) < D < a + b)` — компактный подсчёт
числа выполнений условия.

## 2.2. Функция `find_distance_for(target)`

**Назначение.** Решает обратную задачу: по желаемому числу пересечений `target`
находит подходящее расстояние `D` между звёздами.

**Входные данные.** `target` — желаемое число пересекающихся пар орбит (целое).

**Выходные данные.** Пара `(best_D, best_c)`: найденное расстояние и реально
достижимое при нём число пересечений (точное попадание не всегда возможно, поэтому
берётся ближайшее).

**Алгоритм и математика.** Используется ключевая закономерность: **чем ближе звёзды,
тем больше орбит пересекается** (при сближении больше пар попадает в условие
пересечения). Функция перебирает расстояния `D` от 150 до 510 пикселей с шагом 2
(нижняя граница 150 — чтобы звёзды не сливались), для каждого считает число
пересечений через `cross_count(D)`, и запоминает то `D`, при котором число
пересечений ближе всего к `target` (минимальная разница `|c − target|`). Это простой
перебор с поиском минимума отклонения.

Почему перебор, а не формула: зависимость «число пересечений от D» не монотонная и не
выражается простой формулой (она зависит от конкретного набора радиусов), поэтому
проще и надёжнее перебрать расстояния и найти лучшее.

## 2.3. Функция `make_bodies(D)`

**Назначение.** Создать все движущиеся тела (планеты и спутники) обеих звёзд при
заданном расстоянии `D` между звёздами.

**Входные данные.** `D` — расстояние между звёздами (число).

**Выходные данные.** Кортеж `(b1, b2, s1x, s2x)`: список тел первой звезды, список тел
второй звезды, и координаты x обеих звёзд.

**Алгоритм.**
1. Координаты звёзд: `s1x = CENTER_X − D/2` (левее центра), `s2x = CENTER_X + D/2`
   (правее центра). Так звёзды симметричны относительно центра, между ними `D`.
2. Цикл по орбитам первой звезды (номера 1..16). Для каждой орбиты:
   - радиус берётся из R1;
   - знак скорости: `sign = +1` если номер чётный (вращение по часовой), `−1` если
     нечётный (против часовой) — это требование билета про направление;
   - создаётся планета (словарь с полями: центр, радиус орбиты, множитель скорости k,
     стартовый угол, цвет, номер звезды, признак спутника). Множитель `k = sign ·
     (16 − n + 1)` — внешние орбиты медленнее (для n=1 это 16, для n=16 это 1). Это
     стартовое значение, отжиг потом подберёт величину;
   - если номер планеты есть в MOONS1, добавляется спутник на радиусе `r + 7` (рядом
     с планетой), с той же скоростью и направлением.
3. Аналогичный цикл по орбитам второй звезды (номера 1..20) с центром `s2x`.

**Математика направления.** Чётность определяется через `n % 2` (остаток от деления
на 2). Знак множителя `k` задаёт направление вращения: при движении `φ = φ₀ +
k·BASE_STEP·t` положительный `k` увеличивает угол (одна сторона), отрицательный —
уменьшает (другая сторона).

## 2.4. Функция `min_gap(b1, b2, step=1)`

**Назначение.** Найти минимальное расстояние, на которое за весь период сближались
тела **разных** звёзд. Это главная проверочная функция: если результат больше
диаметра планеты, столкновений нет.

**Входные данные.**
- `b1`, `b2` — списки тел первой и второй звезды;
- `step` — шаг по тикам (1 = проверять каждый тик, точно; больше = быстрее, грубее).

**Выходные данные.** Число — минимальный зазор между телами разных звёзд за период
(пиксели).

**Алгоритм и математика.**
1. `md = 1e30` — начальное «минимальное расстояние» (очень большое, чтобы любое
   реальное оказалось меньше).
2. Цикл по времени `t` от 0 до конца периода с шагом `step`.
3. На каждом `t` вычисляются положения всех тел по формуле движения по окружности:
   ```
   x = cx + r · cos(φ₀ + k · BASE_STEP · t)
   y = cy + r · sin(φ₀ + k · BASE_STEP · t)
   ```
4. Двойной цикл по парам «тело первой звезды — тело второй звезды». Для каждой пары
   считается **квадрат** расстояния:
   ```
   d² = (x₁ − x₂)² + (y₁ − y₂)²
   ```
5. Если `d²` меньше текущего минимума, минимум обновляется.
6. В конце возвращается `√md` — настоящее минимальное расстояние.

**Почему квадрат расстояния, а не само расстояние.** Квадратный корень — монотонная
функция: если `a < b`, то `√a < √b`. Значит сравнивать квадраты — то же самое, что
сравнивать расстояния, но без вычисления корня (который медленнее). Корень берётся
один раз в конце.

**Почему только пары разных звёзд.** Планеты одной звезды летают по окружностям с
общим центром (звезда), но разными радиусами. Концентрические окружности разного
радиуса никогда не пересекаются. Значит планеты одной звезды не могут столкнуться, и
проверять их не нужно — это сокращает работу примерно вдвое.

## 2.5. Функция `solve(b1, b2, seed=5)` — главный алгоритм подбора

**Назначение.** Подобрать стартовые углы и величины скоростей всех планет так, чтобы
минимальный зазор за период стал большим (планеты разошлись и не сталкиваются). Метод
— имитация отжига.

**Входные данные.**
- `b1`, `b2` — списки тел (функция меняет их поля `phase` и `k`);
- `seed` — зерно случайности (для воспроизводимости).

**Выходные данные.** Число — лучший достигнутый зазор. Побочный эффект: тела получают
подобранные углы и скорости.

**Алгоритм.**

*Инициализация.* `random.seed(seed)` фиксирует случайность. Затем всем телам ставятся
случайные стартовые углы (от 0 до 2π) и случайные величины скоростей (от 1 до 18) с
**сохранением знака** (направление вращения по чётности менять нельзя).

*Вложенная функция `new_k(old)`.* Возвращает новое значение скорости с тем же знаком,
что у старого: `sign(old) · random.randint(1, 18)`. Нужна, чтобы при пробах менять
величину скорости, но не направление.

*Вложенная функция `anneal(step, iterations, T0)`.* Один проход отжига:
- `cur` — текущий зазор, `best` — лучший за всё время, `best_state` — копия лучшей
  расстановки, `T = T0` — стартовая температура.
- Цикл `iterations` раз: выбирается случайное тело; с вероятностью 60% меняется его
  стартовый угол, иначе (40%) — величина скорости; старое значение запоминается.
- Считается новый зазор `cand`.
- **Правило принятия:** изменение принимается, если `cand ≥ cur` (стало не хуже), ИЛИ
  с вероятностью `exp((cand − cur) / T) · 0.1` (даже если стало хуже). Иначе
  изменение откатывается.
- Если принятый зазор — лучший за всё время, он и расстановка сохраняются.
- Температура уменьшается: `T ← T · 0.9995` («остывание»).
- Досрочный выход, если зазор стал заметно больше нужного.
- В конце восстанавливается лучшая найденная расстановка `best_state`.

*Два прохода.* Сначала грубый (`step=3`, 2000 проб) — быстро найти хорошую область.
Потом точный (`step=1`, 2500 проб) — довести расстановку с точной проверкой.

**Математика метода** подробно разобрана в разделе 5.

## 2.6. Функция `save_config(filename, b1, b2, s1x, s2x, crossings)`

**Назначение.** Записать итоговую расстановку в текстовый файл для графики.

**Входные данные.** Имя файла, списки тел, координаты звёзд, выбранное число
пересечений (для записи в шапку файла).

**Выходные данные.** Нет (создаётся файл на диске).

**Алгоритм.** Вложенная функция `line(b)` превращает одно тело в строку текста:
определяет имя типа (Satellite/Planet), радиус кружка (2 для спутника, иначе 4) и
собирает строку формата `Тип Радиус Цвет НомерЗвезды ЦентрX ЦентрY РадиусОрбиты K
Фаза`. Затем формируется список строк: комментарии-заголовки, строка первой звезды и
строки всех её тел, строка второй звезды и её тел. Всё записывается в файл в кодировке
UTF-8.

**Зачем единый формат.** Графика читает файл тем же форматом, в котором он записан,
поэтому решатель и графика согласованы: что записано, то и прочитается.

## 2.7. Функция `ask_crossings()` — взаимодействие с пользователем

**Назначение.** Спросить у пользователя желаемое число пересечений и проверить
корректность ввода.

**Входные данные.** Нет (читает с клавиатуры).

**Выходные данные.** Корректное число в диапазоне [MIN_CROSSINGS,
MAX_WORKABLE_CROSSINGS].

**Алгоритм.**
1. Печатает пояснения: всего пар орбит, допустимый диапазон, и почему есть верхний
   предел.
2. Входит в бесконечный цикл `while True`, который повторяется до получения
   корректного значения.
3. В блоке `try ... except` пытается прочитать ввод и превратить в целое число. Если
   введено не число (ошибка `ValueError`) или ввод оборвался (`EOFError`) — печатает
   сообщение и повторяет запрос.
4. Проверяет границы: меньше минимума — «слишком мало»; больше максимума — «слишком
   много»; в обоих случаях повторяет запрос. Если число в границах — возвращает его.

**Зачем проверка ввода.** Защищает от некорректных данных: нечисловой ввод не уронит
программу, а слишком большое/малое число будет отклонено с понятным сообщением.

## 2.8. Функция `main()` — связывает всё вместе

**Назначение.** Запустить весь процесс по шагам.

**Алгоритм.**
1. `ask_crossings()` — спросить желаемое число пересечений.
2. `find_distance_for(target)` — перевести это число в расстояние `D`, узнать реально
   достижимое число пересечений.
3. Напечатать выбор пользователя, расстояние и процент.
4. `make_bodies(D)` — создать тела.
5. `solve(b1, b2)` — подобрать безопасную расстановку.
6. `min_gap(b1, b2, step=1)` — посчитать итоговый зазор **точно** (на каждом тике).
7. Напечатать результат (безопасно/предупреждение).
8. `save_config(...)` — записать конфигурацию.
9. Напечатать подсказку запустить графику.

# 3. Файл `solar_main.py` — графика

Параметры, класс `Body`, функция чтения, отрисовка, анимация, кнопка.

## 3.0. Параметры

- `WIDTH = 1000`, `HEIGHT = 800` — размеры окна.
- `BASE_STEP = 0.01` — базовый шаг угла. **Обязан совпадать** с шагом в решателе,
  иначе движение отличалось бы от того, что подбиралось.
- `CONFIG_FILE = "ticket6_state.txt"` — имя файла с расстановкой.

## 3.1. Класс `Body`

**Назначение.** Описывает одно тело: звезду, планету или спутник. Звезда неподвижна;
планета и спутник движутся по окружности.

### Метод `__init__(self, kind, R, color, cx, cy, orbit_r, k, phase)`

**Назначение.** Конструктор — сохраняет параметры тела при создании.

**Входные данные.** Тип тела, радиус кружка, цвет, центр орбиты (cx, cy), радиус
орбиты, множитель скорости k, стартовый угол phase.

**Что делает.** Сохраняет все параметры в поля объекта. Дополнительно заводит поля
`angle` (текущий угол, стартует с phase), `image` (id кружка на холсте, пока пустой),
`orbit_id` (id нарисованной орбиты, для кнопки).

### Метод `position(self)`

**Назначение.** Вернуть текущие экранные координаты тела.

**Выходные данные.** Пара `(x, y)`.

**Алгоритм и математика.** Если тело — звезда, возвращается её центр (она не
движется). Иначе вычисляется точка на окружности по текущему углу:
```
x = cx + orbit_r · cos(angle)
y = cy + orbit_r · sin(angle)
```
Это формула движения по окружности (см. раздел 5.1).

## 3.2. Функция `read_config(filename)`

**Назначение.** Прочитать тела из текстового файла и создать объекты `Body`.

**Входные данные.** Имя файла.

**Выходные данные.** Список объектов `Body`.

**Алгоритм.** Открывает файл, идёт по строкам. Пропускает пустые строки и комментарии
(начинаются с #). Каждую строку разбивает по пробелам. Если первое слово «Star» —
создаёт звезду (радиус орбиты, k, фаза равны нулю, она неподвижна). Иначе (Planet или
Satellite) создаёт тело с полным набором параметров из строки. Поле star_id графике
не нужно (движение уже задано числами), поэтому пропускается.

## 3.3. Блок первой отрисовки (на уровне модуля)

После чтения тел создаётся окно и холст. Затем два цикла:
1. Рисует орбиты **один раз** (они не двигаются): для каждой планеты и спутника
   рисуется серая окружность, её id сохраняется (для кнопки).
2. Рисует сами тела **один раз**: для каждого тела рисуется закрашенный кружок, id
   сохраняется (чтобы потом двигать, а не рисовать заново).

## 3.4. Функция `update()`

**Назначение.** Один кадр анимации: сдвинуть все тела и перерисовать. Вызывает сама
себя по таймеру — получается непрерывное движение.

**Алгоритм и математика.** Цикл по всем телам: звёзды пропускаются. Для остальных:
- `angle += k · BASE_STEP` — увеличивает угол (скорость = k × шаг, знак k задаёт
  направление);
- через `position()` берутся новые координаты;
- `canvas.coords(...)` перемещает уже нарисованный кружок (быстрее, чем рисовать
  заново).

В конце `window.after(20, update)` просит выполнить `update` снова через 20 мс. Так
получается ~50 кадров в секунду — плавная анимация.

## 3.5. Функция `toggle_orbits()`

**Назначение.** Включить или выключить показ орбит (кнопка из условия билета).

**Алгоритм.** Переключает флаг `show_orbits`. В зависимости от флага выбирает
состояние «normal» (видно) или «hidden» (спрятано). Для каждого тела с орбитой меняет
её видимость через `itemconfig`. Орбиты не удаляются, только меняют видимость —
поэтому повторное включение мгновенно. Меняет надпись на кнопке.

# 4. Файл `ticket6_state.txt` — формат конфигурации

Текстовый файл, который записывает решатель и читает графика. Строки бывают трёх
типов:

```
Star      R цвет x y
Planet    R цвет star_id cx cy orbit_r k phase
Satellite R цвет star_id cx cy orbit_r k phase
```

Поля планеты/спутника: радиус кружка, цвет, номер звезды, центр орбиты (cx, cy),
радиус орбиты, множитель скорости k (со знаком — задаёт направление), стартовый угол.
Строки, начинающиеся с #, — комментарии. Этот файл — «мост» между решателем (который
вычисляет числа) и графикой (которая по числам рисует).

# 5. Математические алгоритмы (углублённо)

## 5.1. Движение по окружности

Точка на окружности радиуса `r` с центром `(cx, cy)`:
```
x = cx + r · cos(φ)
y = cy + r · sin(φ)
```
Это следует из определения синуса и косинуса: на единичной окружности точка под углом
φ имеет координаты `(cos φ, sin φ)`. Умножение на `r` растягивает до радиуса `r`,
прибавление `(cx, cy)` переносит центр. Точка всегда на окружности, потому что
`(x−cx)² + (y−cy)² = r²(cos²φ + sin²φ) = r²` (основное тригонометрическое тождество
`cos²φ + sin²φ = 1`).

Угол растёт линейно во времени: `φ(t) = φ₀ + k · BASE_STEP · t`, где φ₀ — стартовый
угол, k — целый множитель скорости, t — номер тика.

## 5.2. Период и почему скорости кратные

Период — время, после которого система возвращается в исходное состояние. Полный
оборот = 2π. Базовый угол растёт на BASE_STEP за тик, значит период:
```
PERIOD_TICKS = 2π / BASE_STEP ≈ 628 тиков
```
За период планета с множителем k поворачивается на:
```
Δφ = k · BASE_STEP · PERIOD_TICKS = k · BASE_STEP · (2π / BASE_STEP) = k · 2π
```
Это **ровно k полных оборотов** (k целое!), и планета возвращается в старт. Все
планеты возвращаются одновременно, картинка повторяется. **Если бы k было нецелым**,
планета оказалась бы не в стартовой точке, и периода бы не было. Поэтому кратность
(целые k) — обязательное условие существования периода.

## 5.3. Проверка столкновений

Расстояние между точками — по теореме Пифагора:
`d = √((x₁−x₂)² + (y₁−y₂)²)`. В коде сравниваются **квадраты** `d² = (x₁−x₂)² +
(y₁−y₂)²`, потому что корень монотонен (`a < b ⇔ √a < √b`), и сравнение квадратов
эквивалентно сравнению расстояний, но без медленного корня. Корень берётся один раз в
конце.

Условие пересечения двух окружностей (радиусы a, b, расстояние между центрами D):
`|a − b| < D < a + b`.

## 5.4. Имитация отжига — математика

**Целевая величина** — минимальный зазор за период (хотим максимизировать).

**Правило принятия ухудшения.** Если изменение ухудшает зазор (`cand − cur < 0`), оно
принимается с вероятностью:
```
P = exp((cand − cur) / T) · 0.1
```
Поскольку `cand − cur < 0`, показатель отрицательный, и `exp` даёт значение от 0 до 1
(вероятность). Чем сильнее ухудшение, тем меньше P (большие жертвы редки). Температура
T в знаменателе: при большой T дробь близка к 0, exp ≈ 1 (ухудшения принимаются
охотно — «горячо»); при малой T дробь — большое отрицательное число, exp ≈ 0
(ухудшения почти не принимаются — «холодно»). Множитель 0.1 делает метод осторожнее.

Числовой пример (ухудшение на 2 пикселя):
- T = 1.0: P ≈ 1.35%;
- T = 0.5: P ≈ 0.18%;
- T = 0.1: P ≈ 0%.

**Зачем принимать ухудшения.** Чтобы не застрять в локальном максимуме. Если всегда
только улучшать, метод останавливается на первом «холмике». Чтобы найти вершину выше,
иногда нужно спуститься (принять ухудшение). Это позволяет вероятностное принятие.

**Остывание.** После каждой пробы `T ← T · 0.9995` — температура плавно падает.
Сначала метод широко исследует, в конце аккуратно дорабатывает.

**Сохранение лучшего.** Поскольку метод иногда уходит в худшие состояния, отдельно
хранится лучшая найденная расстановка, и в конце метод возвращается к ней.

**Две стадии.** Грубая (step=3) — быстро найти область. Точная (step=1) — довести.
Финал обязательно на step=1, иначе грубая сетка пропустила бы сближения между тиками
и зазор оказался бы ложным.

# 6. Идея работы решателя и обоснование проверок

## 6.1. Идея решателя в целом

Решатель решает задачу, которая на первый взгляд кажется противоречивой: орбиты двух
звёзд должны **пересекаться**, но планеты при этом **не должны сталкиваться**.
Подход:

1. **Кинематическая модель.** Планеты движутся по заданным окружностям (а не под
   действием физических сил). Это даёт полный контроль над движением.
2. **Кратные скорости → периодичность.** Скорости целочисленно кратны базовому шагу,
   поэтому движение повторяется через период. Это превращает задачу «не сталкиваться
   никогда» (бесконечную) в задачу «не сталкиваться за один период» (конечную).
3. **Подбор расстановки.** Имитацией отжига подбираются стартовые углы и скорости так,
   чтобы за период минимальный зазор был большим.
4. **Параметр пересечений (особенность Варианта 2).** Пользователь задаёт число
   пересечений, решатель переводит его в расстояние между звёздами.

## 6.2. Почему проверка устроена именно так

**Почему проверяем по всему периоду, а не «на глаз».** Столкновение — это сближение в
какой-то момент времени. Чтобы гарантировать его отсутствие, надо проверить все
моменты периода. Поскольку движение периодично, проверки одного периода достаточно для
гарантии навсегда. Это строгое доказательство, а не наблюдение.

**Почему проверяем только пары разных звёзд.** Планеты одной звезды летают по
концентрическим окружностям разного радиуса — они геометрически не могут пересечься.
Проверять их — лишняя работа. Исключение этих пар сокращает вычисления вдвое и не
теряет ни одного реального риска.

**Почему сравниваем квадраты расстояний.** Эквивалентно сравнению расстояний (корень
монотонен), но быстрее (без вычисления корня). При сотнях тысяч сравнений за прогон
это важно.

**Почему две стадии и финал на каждом тике.** Грубая проверка (через несколько тиков)
быстрая, но может **пропустить** сближение между проверенными моментами — и показать
ложно большой зазор. Поэтому грубая стадия только для быстрого поиска области, а
итоговая гарантия даётся точной проверкой на **каждом** тике. Это устраняет ошибку
дискретизации (она реально возникала: грубая проверка показывала зазор 11 px, точная —
что планеты почти касаются).

**Почему ограничен диапазон выбора в Варианте 2.** Чем больше пересечений, тем теснее
система и тем меньше достижимый зазор. Выше ~100 пересечений планеты нормального
размера не помещаются (проверено экспериментально). Поэтому решатель не даёт задать
больше — это защита от заведомо нерешаемого запроса.

**Какие ошибки ловят проверки.**
- Проверка ввода (`ask_crossings`) ловит нечисловой ввод и выход за границы.
- Проверка пересечений (`cross_count`) гарантирует, что условие билета «орбиты
  пересекаются» выполнено.
- Проверка зазора (`min_gap`) ловит любое опасное сближение планет за период.
- Финал на step=1 ловит сближения, которые грубая сетка пропустила бы.

# 7. Раздел про `#FIXME`

**Важно:** в самом Варианте 2 меток `#FIXME` нет — этот вариант написан с нуля как
кинематическая модель. Метки `#FIXME` были в **исходной заготовке преподавателя** —
это пять модулей с **физическим** движком (гравитация Ньютона), которые дорабатывались
в отдельном (физическом) архиве. Ниже разобран каждый `#FIXME` из той заготовки: идея,
реализация и причина выбора подхода. Это нужно для полноты картины, поскольку именно с
закрытия этих FIXME началась работа над билетом.

## FIXME 1 — `calculate_force` (модуль `solar_model.py`)

**Что было.** Заглушка: `body.Fx += 1`, `body.Fy += 2` (фиктивные значения силы).

**Идея.** Нужно вычислить реальную силу гравитационного притяжения между телами по
закону всемирного тяготения Ньютона.

**Реализация.** Модуль силы: `F = G · m₁ · m₂ / r²`, где G — гравитационная
постоянная, m₁, m₂ — массы, r — расстояние. Сила направлена вдоль линии между телами.
Раскладывается на оси через единичный вектор направления:
```
Fx += F · (dx / r)
Fy += F · (dy / r)
```
где dx, dy — разности координат, r — расстояние. Добавлена защита от деления на ноль
(если тела совпали).

**Почему так.** Это точная формула гравитации; проекции через dx/r и dy/r — стандартный
способ разложить силу на оси. Иначе планеты не притягивались бы к звёздам.

## FIXME 2 — `move_space_object` (модуль `solar_model.py`)

**Что было.** Заглушка: `body.x += 42`, пересчёт y отсутствовал.

**Идея.** Переместить тело по действующей на него силе, то есть численно
проинтегрировать уравнения движения.

**Реализация.** Метод Эйлера — простейшее численное интегрирование:
```
a = F / m            (ускорение из второго закона Ньютона)
V = V + a · dt       (новая скорость)
x = x + V · dt       (новая координата)
```
То же по обеим осям.

**Почему так.** Метод Эйлера прост и нагляден, подходит для учебной задачи. Его минус
(накопление ошибки) компенсируется мелким шагом dt. Более точные методы (Верле,
Рунге–Кутты) сложнее и для демонстрации избыточны.

## FIXME 3 — `scale_y` (модуль `solar_vis.py`)

**Что было.** Заглушка: `return y` (без масштабирования).

**Идея.** Перевести физическую координату y в экранную, как это делает `scale_x`, но с
учётом, что ось Y на экране направлена вниз, а в модели вверх.

**Реализация.** `return -int(y · scale_factor) + window_height // 2`. Минус
переворачивает ось (иначе система отображалась бы вверх ногами).

**Почему так.** Без масштабирования координаты не помещались бы на экран; без знака
минус направление вращения визуально было бы перевёрнуто. Это прямо влияет на
требование «по часовой/против».

## FIXME 4 — `create_planet_image` (модуль `solar_vis.py`)

**Что было.** Заглушка: `pass` (планета не рисовалась).

**Идея.** Нарисовать планету так же, как рисуется звезда.

**Реализация.** Перевод координат в экранные через scale_x/scale_y и рисование кружка
нужного радиуса и цвета (`create_oval`).

**Почему так.** По аналогии со звездой — единообразно и просто.

## FIXME 5 — чтение планет в `read_space_objects_data_from_file` (модуль `solar_input.py`)

**Что было.** Заготовка читала только звёзды (комментарий «do the same for planet»).

**Идея.** Добавить разбор строк планет (и спутников).

**Реализация.** Добавлены ветки: если тип строки «planet» — создать планету и разобрать
её параметры; «satellite» — создать спутник. Формат строки одинаковый.

**Почему так.** Без этого планеты не читались бы из файла, и система состояла бы только

## FIXME 6 — `parse_star_parameters` и `parse_planet_parameters` (модуль `solar_input.py`)

**Что было.** Заглушки: `pass` (параметры не разбирались).

**Идея.** Разобрать строку конфига на отдельные параметры тела.

**Реализация.** Строка разбивается по пробелам, и значения раскладываются по полям
(радиус, цвет, масса, координаты, скорость) с преобразованием типов (int для радиуса,
float для чисел).

**Почему так.** Прямое сопоставление позиций в строке полям объекта — простейший и
надёжный способ разбора.

## FIXME 7 — `write_space_objects_data_to_file` (модуль `solar_input.py`)

**Реализация.** Для каждого тела формируется строка с его настоящими параметрами (тип,

**Почему так.** Чтение и запись должны быть согласованы — иначе сохранённый файл не
открылся бы обратно.
